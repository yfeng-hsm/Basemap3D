Student setup

Install once. Run the notebook from top to bottom.

Open planning notebook in Colab ↗Open population notebook in Colab ↗

No local setup is needed for Colab. Run the setup cell, then the remaining cells. The wrapper automatically serves scene HTML through Colab’s official iframe proxy; no Go Live or manual server command is needed. A Google sign-in may be required. Browser WebGL2 and internet access are still needed.

For a local installation, use Python 3.10 or newer (3.11+ recommended), JupyterLab and a browser with WebGL2 and hardware acceleration. Download and unzip the complete repository, then open a terminal in its root directory.

macOS / Linux

python3 -m venv .venv
.venv/bin/python -m pip install -e ".[notebook]"
.venv/bin/python -m jupyterlab

Windows PowerShell

py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[notebook]"
.\.venv\Scripts\python.exe -m jupyterlab

Open Mainz_3D_5_Tasks.ipynb or Population_3D_Columns.ipynb and use the same environment's Python kernel. Keep data/ and basemap3d/ with the notebook. QGIS, Node.js, Docker and a Cesium ion account are unnecessary for this configuration.

Notebook and browser outputs: finish a cell with m to display it. Call m.save(...) to write HTML. Trust your own notebook before running interactive output. GitHub's source viewer does not execute the 3D scenes.
A small public API

Familiar Python, with clear scope.

Map, WmsTileLayer, GeoJson, NearbyBuildings, SunShadows and BarLayer share the .add_to(m) pattern. Use .copy() to preserve an earlier step.

The wrapper is independent of Folium and is not a complete Folium-compatible API. It keeps the classroom interface simple while CesiumJS handles the official 3D tiles.

Read the API reference

Coordinate conventions

Map(location=[latitude, longitude])
GeoJSON: [longitude, latitude], WGS84.

Data stays outside code

Your polygons and population CSV live in separate files. Nearby OSM building footprints are fetched automatically for your polygons and cached for 24 hours. Official building and terrain tiles are streamed online, not stored in the course package.

Results can be shared

Exported HTML embeds its configuration and local vector data. The official map and model services still need an internet connection.

Interpret the result

A teaching viewer, with documented assumptions.

What does the nearby-building query select?

Original OSM footprints within the chosen local planar distance of any input polygon. Gold is applied to the corresponding space in the official model. A separate 3 m visual margin improves coverage but does not change selection or counts. OSM and LoD2 do not share a guaranteed object match.

How are shadows calculated?

The date and Europe/Berlin local time set Cesium's sun position. LoD2 surfaces cast ground shadows. Photo shadows are already baked into the aerial imagery and remain unchanged. This is not a certified solar or thermal assessment.

Can I use another study area?

Yes. Supply your own WGS84 Polygon or MultiPolygon file and call NearbyBuildings(). The downloader derives its area from those polygons, with no Mainz fallback. A local building GeoJSON is optional. Automatic retrieval is intended for small study areas (up to 12 small bounding-box requests); larger areas need your own footprint file. The raster example is an RLP DOP20 preset.
